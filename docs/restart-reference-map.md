# Bluewing restart reference map

Read an entry when working on that area. This is a lookup guide, not a prerequisite reading list. The [restart brief](restart-brief.md) describes the new direction; the old code and documentation are examples to evaluate, not requirements to reproduce.

## Location and authority

`REFERENCE` means the old PlanVyper repository wherever it has been placed on this machine. Every code/document path below is relative to that root. For example, sibling folders might be `workspace/PlanVyper-reference/` and `workspace/Bluewing/`; their names are not requirements.

Keep the reference outside the new app's source tree, package workspace, builds, and default agent instructions. Keep one locally recorded path to it. Load specific files to answer specific questions. Any imported component becomes ordinary owned code in the new application, with its dependencies reviewed.

The assessment used checkpoint `checkpoint_84836d3c80c41372`, tree `tree_84836d3c80c41372806bee23b44a21eb67dc12624a0cbff4d9d3a46900225b2e`. The ordinary Git checkout `1738faab46fee3878f34c497bff39b19c3096bf0` differed in 62 of 191 assessed source paths. That commit alone does not preserve all tested fixes.

Before transporting the reference, preserve the assessed source as an ordinary Git snapshot or source archive, including its source manifest. The manifest is `docs/assessments/2026-09-16/evidence/assessment-manifest.json`. It records repository-relative paths and hashes. Preserve the assessment evidence alongside the source. The new project should not need Sunlight to inspect or build its reference. The temporary assessment directory is not a durable reference location.

## Documentation that needs interpretation

`docs/PlanVyper_Product_Technical_Spec_v1_1.html` and Addenda 01–06 record evolving choices. Their statements of authority apply to the old implementation. Consult a relevant section to understand a problem; carry a behavior into the new brief only after deciding it is still wanted.

In particular, `apps/desktop/README.md` describes an intentionally independent CLI, read-only browser preview, and extensive history behavior. Those are not instructions for the restart. Addendum 06's separate desktop/CLI writer model is also superseded by the requested desktop-dependent CLI.

`docs/assessments/2026-09-16/report.md` records what was inspected, what passed, and what remained unverified. Use it to judge evidence strength. It does not certify the old application's correctness or provide a reliable remaining-effort percentage.

## What to bring into the new project

Start with the brief, this map, and a small set of representative plans and independently checked results. Copy visual components or algorithms when they solve a current task and their assumptions are understood. Maintain one current statement of product behavior in the new project; update it directly as decisions change.

Keep the reference runnable for comparisons where practical. A mismatch calls for checking the intended behavior, not automatically making the replacement imitate the old app.
